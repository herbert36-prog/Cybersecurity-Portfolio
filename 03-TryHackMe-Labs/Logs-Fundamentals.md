## Task 1 – Introduction to Logs

### What are logs?

Logs are records of activities taking place on a computer system, application or network.

They provide information about what happened, when it happened and sometimes which user or device was responsible.

For cybersecurity analysts, logs are important because they provide evidence that can help reconstruct events during an investigation.

For example, if an unauthorised user attempts to access an account, authentication logs may record the failed login attempts.

### Why are logs important?

**Security monitoring:** Logs help analysts identify unusual behaviour and potentially suspicious activity.

**Incident investigation:** Analysts can examine logs to understand what happened during a security incident.

**Troubleshooting:** System and application logs can help identify errors and technical problems.

**Performance monitoring:** Logs can provide information about application and system performance.

**Auditing:** Logs provide records of activities that can support security reviews and compliance requirements.

## Task 2 – Types of Logs

Different logs record different types of activity. Understanding the differences helps analysts identify where to look during an investigation.

### System Logs

Record operating system events, including startup activity, shutdowns and system errors.

### Security Logs

Record security-related events, including authentication attempts, account changes and access-related activity.

### Application Logs

Record events generated by software applications, including errors and application activity.

### Network Logs

Record network-related activity, which can include connections, communication and traffic passing through network devices.

### Web Server Access Logs

Record requests made to a web server.

These can contain information such as:

- Client IP address.
- Date and timestamp.
- HTTP request method.
- Requested URL.
- HTTP response status code.
- User-agent information.

Understanding these fields helps analysts investigate web activity and identify potentially suspicious requests.

## Task 3 – Windows Event Logs Analysis

### What are Windows Event Logs?

Windows Event Logs record activities occurring within a Windows operating system.

They can be examined using Windows Event Viewer, which provides an interface for reviewing and filtering recorded events.

Windows logs are particularly useful during investigations involving authentication, account management and system activity.

### Windows Event Viewer

Event Viewer allows analysts to examine events recorded by Windows.

The Security log is particularly important for cybersecurity investigations because it records security-related activity.

### Understanding Event IDs

Windows uses numerical Event IDs to identify particular types of events.

Two examples covered in the investigation are:

| Event ID | Description |
|---|---|
| 4720 | A user account was created |
| 4724 | An attempt was made to reset an account's password |

These events can help analysts investigate account-management activity.

For example, an unexpected account creation event may require further investigation to establish who created the account and why.

### Investigation Process

The Windows Event Logs exercise involved examining Security events and reviewing account-related activity.

The investigation process included:

1. Opening Windows Event Viewer.
2. Navigating to the Windows Security log.
3. Filtering or identifying relevant Event IDs.
4. Examining the details of individual events.
5. Reviewing usernames and timestamps.
6. Understanding what the recorded activity represented.

### Security Relevance

Account creation and password changes can be legitimate administrative activities.

However, unexpected account-management events may indicate suspicious behaviour, particularly if an unauthorised account has been created.

Analysts should examine the surrounding events and establish whether the activity was authorised before deciding whether escalation is necessary.

## Task 4 – Web Server Access Logs Analysis

### Understanding Web Server Access Logs

Web server access logs record requests made by users or devices when accessing a website.

These records can help administrators and security analysts understand how a website is being accessed.

For example, repeated requests to unusual URLs or unexpected activity from a particular IP address may require further investigation.

### Linux Command-Line Investigation

The exercise introduced Linux commands for examining and searching web server access logs.

**Displaying log contents using cat**

```bash
cat access.log
```

The `cat` command displays the contents of a file.

**Searching logs using grep**

```bash
grep "/contact" access.log
```

The `grep` command searches for matching text within a file.

This allowed me to narrow down the log entries to requests involving a particular URL.

**Searching for a specific IP address**

```bash
grep "172.16.0.1" access.log
```

This searches the access log for entries associated with the specified IP address.

### Understanding HTTP Requests

The exercise involved examining GET and POST requests.

**GET requests**

GET requests are generally used to retrieve information from a web server, such as requesting a webpage.

**POST requests**

POST requests are generally used to submit information to a web server, such as submitting a form.

Understanding these methods helps analysts interpret the activity recorded in web server access logs.

### Practical Investigation

The web server log exercise required examining access log entries to identify:

- Which IP address made the latest GET request to a particular URL.
- When a particular IP address made its latest POST request.
- Which URL was requested during that POST request.

This required searching the log entries and interpreting the IP addresses, HTTP methods, timestamps and requested URLs.

### Security Relevance

Web server logs can provide useful evidence when investigating suspicious web activity.

For example, repeated requests to different URLs could indicate automated scanning, while unusual POST requests may require additional investigation.

However, individual requests should not automatically be treated as malicious. Analysts need to consider the wider context and other available evidence.
